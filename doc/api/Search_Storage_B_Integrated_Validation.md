## 首轮记录（历史）

以下保留前一迁移步骤版本的结果与诊断过程，不作为最终构建的验收替代。

## 1. 来源和执行条件

- 冻结 schema 5 / external-content / tokenization 3 / Metadata rev 2 快照 r793。
- 909,342 条音频、20,248 个目录、39 条扫描会话。这个样本不足 1M 条，
  不代替 **P95 latency <500ms for 1M+ records** 的验收。
- 原始主文件及新建输入副本 SHA256 相同：
  `337d4bb898883a36a3980925e596844ba5effe22484a945a91bc55879736ae51`。
- 通过隔离 release `AudioLibCli db migration plan/apply/verify/rollback` 执行，
  没有对业务库手写删除 SQL。SQLite 3.54.1，workspace release 查询代码。
- AMD Ryzen 7 9800X3D、约 96 GiB RAM、本机 WD_BLACK SN8100 NVMe。
  迁移期间同时运行开发编译与测试；下列耗时不是独占机器基准。
  搜索计时没有本任务的并行构建/迁移负载，OS 缓存未清空、机器未独占。
- 迁移目标 `ale-s6-cld1-t3-m2-p0`：删除六个持久化派生分词列、退役播放结构，
  保留十二个 FTS 逻辑字段及完整位置，tokenization 仍为 3。

## 4. 搜索一致性与首次性能记录

新增 opt-in、默认忽略的 `full_library_validation` release 测试只读打开显式指定的文件，
报告必须使用尚不存在的文件路径。
它不自动迁移查询输入；若 provider 换成临时升级副本会直接失败。

- 每条文档的 FTS 长度与全局统计完全一致。
- 1,198,133 个词项的文档频次和出现次数完全一致。
- 58 类文本查询比较全量命中 ID 和 native BM25 的逐位分数摘要。
  包含字对片段、中英文、组合重音、大小写折叠、标点、数字、操作符字面文本和无结果查询。
- 自定义 BM25 再对照目标库的 native BM25，最大误差 0 ULP。
- 86 个请求覆盖排序、分页、过滤及目录范围，连续 3 轮共 258 对：
  有序页面 DTO、总数、返回数和目录统计摘要全部一致。唯一归一化的 DTO 字段是
  已明确退役的 `play_count`；`last_played_at` 另按 SQL 逐行核对。

下表为**目录统计修复前**记录。每轮复用各自 provider；第 0 轮不是磁盘冷缓存。

| 轮次 | 原库搜索 P95 | 新库搜索 P95 | 原库搜索+目录 P95 | 新库搜索+目录 P95 |
|---|---:|---:|---:|---:|
| 0 | 306.1 ms | 481.9 ms | 424.6 ms | 658.5 ms |
| 1 | 243.2 ms | 375.3 ms | 346.7 ms | 512.2 ms |
| 2 | 236.9 ms | 239.7 ms | 356.4 ms | 357.7 ms |

`metal` + 1–10 秒：新库第 0 轮搜索 101.8 ms，目录统计 1,102.4 ms；
第 2 轮分别 54.9 / 230.3 ms。此长尾不能因搜索 P95 小于 500 ms 而忽略。
随后发现目录统计在复用 BM25 缓存时没有复用数字过滤覆盖索引，已作窄范围修复，
保留全部过滤、取消和回退条件。

### 目录统计修复后复测

另开 provider，先新库后原库；本任务没有并行编译、测试或迁移。仍未控制 OS 缓存或其他
系统负载，因此不能把不同轮次整体延迟变化都归因于该修复。全部 258 对结果在新旧库间、
以及修复前后均一致。

| 轮次 | 新库搜索 P95 | 新库搜索+目录 P95 | 新库时长过滤搜索 | 新库时长过滤目录 | 两项合计 |
|---|---:|---:|---:|---:|---:|
| 0 | 374.7 ms | 437.2 ms | 81.9 ms | 86.0 ms | 167.9 ms |
| 1 | 349.7 ms | 502.6 ms | 78.0 ms | 86.8 ms | 164.9 ms |
| 2 | 336.2 ms | 463.3 ms | 54.0 ms | 50.3 ms | 104.3 ms |

原库同一修复后的时长过滤目录为 53.6–63.3 ms。这支持将已识别的目录统计慢路径
归因于访问策略，而非改变字对编码。新库第 0 轮仍有 `metal` 按 Tags 排序 1,639.2 ms、
按修改时间排序 539.1 ms 的单次请求；这些超限以及 1M+ 条件仍要跟进，不能宣称所有请求
均小于 500 ms 或全量性能验收已完成。

## 5. 100 万条合成库

同一隔离工作区 release `search-benchmark`，新建独立 schema 6 数据库，
`--records 1000000 --queries 100 --folder-facets --fragment-cases --edge-cases --first-provider`。
26 类请求、100 次共享 provider 混合查询，另为每类请求测一次全新只读 provider。
没有并发写入，OS 缓存未清空；生成约 260.21 秒，总运行 276.55 秒，退出码 0。

| 指标 | 实测 |
|---|---:|
| 记录 / 缺失记录 | 1,000,000 / 0 |
| 合成库主文件 | 982,298,624 字节 |
| 共享 provider 搜索页 P95（provider 计时） | 164.4 ms |
| 共享 provider 搜索+目录 P50 / P95 / P99 | 32.4 / 258.2 / 430.5 ms |
| 新 provider 首次搜索 P95（外部计时） | 335.4 ms |
| 新 provider 首次目录统计 P95 | 124.0 ms |
| 新 provider 首次搜索+目录 P95 | **536.8 ms** |
| provider 打开 P95（不计入上述合计） | 34.1 ms |

共享 provider 的 100 次查询有 77 次复用排名缓存。这份合成库的 Metadata 较短、
目录分布简单、文件只有约 0.98 GB，不能代替 10.61 GB 真实库的宽行与目录分布。
该条件下搜索的 **P95 latency <500ms for 1M+ records** 达标；首次串行搜索+目录统计
未达 500 ms，仍单独记录失败。最慢的两项首次合计为 `metal` 按文件名排序 559.1 ms，
`door outdoor` 按相关性排序 536.8 ms。不能把 benchmark 进程退出 0 等同于所有性能门槛通过。
