## 哪些入口会自动迁移

| 入口 / 实际状态 | 行为 |
|---|---|
| 本地可写启动或切库，schema 3–5 / p0 / 过时派生状态 | 自动规划、验证备份、建立受保护任务、转换候选并发布 p1；本地旧历史先导入独立 history.db，成功后才退役主库播放字段 |
| 服务端打开配置的旧权威库 | 同样自动迁移实际配置的库；不导入本机播放历史，不是仅做只读诊断 |
| 完整 p1 再次打开 | 直接使用，不重新备份/重分词/生成新迁移任务 |
| 新客户端收到完整 schema 3–5 / p0 只读快照 | 保持源格式；不因程序版本差异强制转换 |
| 只读快照派生状态过时 | 仅在自有 staging/缓存副本升级，不修改下载源或另一工作库；失败保留原 active cache |
| 明确回滚后的库 | 普通启动拒绝立即再次自动升级；需显式重新 plan/apply |
| schema 1–2 / 旧 Python 库 | 不走普通原地自动升级；先用受支持的只读导入创建 owned Rust 库，再检查迁移路线 |
| 未来 schema / 已知 feature 的更高修订 / 未知必需 feature | 拒绝使用并提示升级/不兼容，不自动重建或丢弃数据 |
| CLI inspect / diagnose / plan | 只读检查，不隐式升级；apply 才执行显式计划 |

自动恢复仅适用于**程序版本、catalog、tokenizer、recipe 和归属**匹配的任务。此次 main 合并改变了源实现指纹；旧分支的未完成任务应先用原工具完成或回滚，不能仅凭相同的 `0.6.0-dev.1` 版本字符串交给新构建接管。完整备份与任务目录保留；不自动清理。

## 旧库影响与首次部署前置检查

业务数据退役范围仅为 `play_history`、`audio_files.play_count`、`audio_files.last_played_at`；退役值仍保留在不可变回滚备份。方案 B 另移除 6 个可重建的 `*_tokenized` 派生列，不删除其他业务列或未知扩展。ID、Metadata、用户标签/注解/收藏、保留的旧 user_rating 和未知扩展必须保持；迁移器同样支持经声明校验的列添加/默认值及字段退役，无法安全转换时阻断。

在服务器构建本 PR 对应源码，使用现有平台目标/feature 与部署方式；确认 `--version` 为候选版本、部署后的 `/api/v1/health` commit 对应实际构建。没有由本任务发布的新 tag/Release。

首次启动前，在维护窗口停止其他库写者，另留一份升级前可恢复的库备份及原服务器二进制。原有迁移任务先按原工具处理。用候选 CLI 的 `db migration inspect/plan` 检查指定的库及空间预算，再启动服务；不要对未知库运行手工 DROP/重扫。

规划器给出的额外可用空间是保守预检：源逻辑页字节的约 5 倍 + 1 GiB；若需旧结构规范化，为约 8 倍 + 1 GiB。以当前计划返回的实际字节数为准，不把迁移后的约 10.6 GB 文件体积当作峰值磁盘需求。

普通本地客户端启动也可能迁移它选择的本地库。测试新版客户端时使用独立 `AUDIOLIB_DATA_DIR`、测试设置和缓存，不覆盖当前安装，不把测试配置指回日常工作库。完整旧远程缓存的读取仍按上表规则处理。

## 用户部署并通知后执行

1. 核对服务端版本/源码 commit、目标库身份及升级前基线。首次库打开期间 health 保持可达并报告阶段/已提交进度，需要库的接口返回 503；完成后才恢复业务可用。
2. 核对实际 schema/feature/p1 身份、迁移完成记录和备份位置；比较条数、稳定 ID、Metadata、用户注解/未知扩展和搜索结果。不要仅看版本字符串断言迁移成功。
3. 正常重启一次，验证不重复迁移、不生成新的备份任务；若未完成，按同构建任务的持久水位恢复。
4. 用匹配新客户端在隔离缓存中同步、查询、排序和目录统计；验证 snapshot 库身份及 revision 下界。旧客户端应明确提示升级，不能“同步成功后无法解码”。
5. 验证新客户端播放不向服务端累计历史；旧 plays 空操作及空 history 不改变业务 revision/data_version。本机事件仅进入当前库的独立 history.db。
6. 若需要实际库回滚测试，先另行确定维护窗口和测试副本；本地回归已验证备份恢复及显式 rollback hold，不能在在线业务库上为验收直接回滚。

远程验收必须基于用户届时通知的服务与实际部署 commit。本机 Windows 临时库结果不是 macOS/Linux 服务器运行验收，也不是当前局域网大库自动升级耗时。
