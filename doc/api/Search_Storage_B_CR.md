| P2 | 两个来源并发导入同一尚不存在的目标，可先后写入同一个本机历史库，再由最终发布决定胜者；普通创建或打开也可能抢占已发布但尚未登记迁移任务的旧副本 | 用目标旁持久锁统一导入与打开身份；导入和缺失目标创建持排他锁，已有目标的可写打开持共享锁至 provider 建成，导入内部仅允许显式且目标匹配的 owner 重入。覆盖两个导入入口、普通/本地创建与已有库打开的互斥，锁 inode 不删除 |
| P2 | 来源 A 先导入历史、后因结构依赖失败，目标仍缺失；随后来源 B 可成功导入同一路径，却混入 A 的历史 | 本地导入先在自有副本做诊断和路线规划，再无覆盖发布旧格式副本，复用最终路径的持久任务执行备份、历史导入及迁移。直接可识别的依赖失败在发布前拒绝；发布后失败保留 A 的自有目标和任务，B 不能覆盖。覆盖失败 A 后合法 B 仅有 B 历史，以及保留目标后从已核验备份恢复，原来源字节不变 |
| P2 | 导入进程在旧副本发布后、任务登记前退出，会丢失只存在于内存中的本地历史 scope；普通打开可按服务端范围跳过历史导入 | 在发布前向持久锁文件写入并同步 protocol、库 ID、canonical 数据根和历史上限。普通创建/打开拒绝待处理本地意图，匹配本地入口按原上限恢复；损坏、未知或超长的非空意图均阻断打开。实际 p1 准备完成后才清意图，清理锁竞争时保留并延后；覆盖无任务崩溃窗口、错误根、损坏意图、共享锁竞争及未发布意图由新显式导入替换 |
| P2 | CLI 显式 `db migration` 直接调用执行器，绕过 provider 的本地导入意图检查；`plan`/`apply` 可使用 `local_history=None` 接管待处理本地导入 | Plan、Apply、Resume、Verify、Rollback 在命令全程持有不透明 owner admission；存在意图时校验本地库身份、根与上限，拒绝服务端范围。只读规划仅锁读既存 receipt，不创建锁目录/文件、不改意图；覆盖无 receipt 不写 sidecar、错误 scope 拒绝与 CLI 规划/应用绕过回归 |
| P2 | 历史根若只保存词法绝对路径，目录链接重定向后可把恢复写入另一个历史位置；导入目标的身份也可能在最终发布前后不一致 | 计划及导入意图绑定 canonical 数据根和由最终目标 canonical 路径生成的本地库 ID，apply/正向 resume 在写入前复核真实根；规划保持只读，显式导入负责创建其已授权数据根。覆盖根不可用或不匹配时源库不变、发布前后库身份一致 |
| P2 | 把历史目录可用性放入所有任务身份检查，会使本机历史盘暂不可用时连 verify/rollback 都无法执行，阻断主库恢复 | 分离持久 scope 身份与历史写入前置条件：verify/rollback 及已进入回滚的 resume 无需访问历史根；若有待处理导入意图，入口仍核对保存的根路径文字、库 ID 和上限，原备份/业务保护继续生效。覆盖移走历史根后完成校验、回滚并保留独立历史，防止恢复流程反向改写 history.db |

## 数据和恢复边界

审查覆盖 typed business digest、隐式 rowid、signed ID、WITHOUT ROWID、序列水位、未知
扩展、授权退役边界、源绑定、备份、管理/扫描/升级租约、批次与游标提交顺序、发布 receipt、
checkpoint 和完整回滚。最新 v6 授权退役 `play_history`、`play_count` 和 `last_played_at`；本地旧历史须在验证备份后先导入独立 history.db，服务端/快照不导入。
后续业务数据或 DDL 变化会阻止回滚覆盖。未发现其他可确证的数据损坏或恢复缺陷。

进程退出测试覆盖 copy/index 的脏页与热 journal、部分 SQLite backup 发布/回滚及已提交
边界；它们不代表真实断电或所有文件系统故障。未知扩展若不能受控转换会阻止升级。
缓存崩溃残留仍保守保留；重试从旧有效缓存开始，不自动认领或回收其他任务。

合并保留主线的 Waveform 缓存管理、同 revision 写响应、独立下载/解压计数、写盘阶段及取消。
两端发布号来自同一 workspace；版本范围不替代下载后实际库格式检查。
