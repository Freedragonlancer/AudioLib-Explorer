# 状态提示生命周期审查（2026-11-13）

范围：桌面全局状态、播放确认、NAS 首响应/缓冲、Waveform 与选区试听、搜索、Metadata 保存、关闭恢复，以及 AI/封面/数据源各自的提示通道。检查生产者、UI 队列交付时的身份校验和提示结束条件；不把底层错误统一静默。

## 确认的问题与修复

| 问题 | 原因 | 修复后的行为 |
| --- | --- | --- |
| 已成功播放仍显示 `Audio acknowledgment: timed out waiting on channel` | GUI 等待 4 秒后丢弃确认接收端，已入队命令继续运行；超时不属于引擎错误，后续状态无法可靠清除 | 新的分段确认 API 保留接收端。GUI 继续等待实际结果，1.5 秒后显示独立“正在准备音频”进度；成功/取消后结束。后续自动播放只在当前请求确认后提交 |
| 选区试听和 Waveform 定位有同类误报 | Load/PlayRange 使用相同的固定确认超时 | 使用相同可取消确认流程；Stop、换素材和换来源立即放弃旧请求的后续操作 |
| 输出设置可能显示失败但稍后实际生效 | 普通 Configure 在 4 秒后返回失败，配置持久化与引擎实际结果脱节 | 设置 worker 等待确定确认后再提交原有配置保存流程，与已有 ConfigureSource 一致 |
| 缓冲结束提示覆盖保存反馈，迟到回调重新显示缓冲 | 缓冲提示写入通用状态，缺少源/音频身份和最新状态校验 | 使用独立缓冲通道；已校验的播放快照发布，Ready/错误/边界/关闭保护均清除；等待计时随来源、库和音频代际重置 |
| 旧 Waveform/预览错误覆盖新选中素材的状态 | worker 检查后到 Slint 交付前，身份仍可能变化 | 在 UI 交付时再次检查任务取消、Waveform/选择代际、来源和库身份；主动取消与读取中断不发布失败 |
| 关闭失败的恢复信息被排队消息覆盖 | 通用状态在入队前检查关闭标记，播放错误分支及远程根重试缺少交付保护；内部搜索刷新丢失恢复文本 | 交付时读取最新关闭保护；内部刷新保留恢复文本及视口锚点；播放位置和实际控件继续更新，被保护的错误转换留待后续处理 |
| 搜索的内部一致性取消显示为用户错误 | 多次查询之间库 revision 变化，通过 Cancelled 丢弃混合结果，却直接进入失败提示 | 单独标记内部 revision 失效，仅此路径重新请求同一作用域/过滤条件，丢弃不一致页；普通取消和真实错误维持原语义 |

## 保留的边界

- NAS 磁盘唤醒只由前台实时等待通道展示，不恢复数据源摘要里的青色持久提示。首响应结束后的解码/引擎等待显示“准备音频”，不声称磁盘仍在唤醒。
- 取消观察不会撤销已经入队的命令；Stop/选择切换仍通过原有 admission 锁、取消源和代际控制后续播放。
- CLI、IPC、管理和关闭流程保留有界确认及数据安全屏障。超出观察预算明确说明“尚未确认，命令可能仍完成”，不谎报执行已取消；真实执行失败和通道断开继续返回错误。
- Metadata 保存/恢复、扫描和库操作使用其已有写入顺序及专属进度。AI、封面和数据源报告沿用各自字段及身份校验，避免用全局清空消除错误而吞掉新反馈。
- 未改数据库格式、扫描协调、Metadata 写入顺序、音频回调或 ASIO 设备实现；不要求重复数据库/服务端/百万记录性能回归。
