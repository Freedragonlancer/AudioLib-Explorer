## 退出完成通知可靠性（2026-10-13，0.4.4 后续修复）

用户再次报告右上角 X 后停留在 Saving changes。隔离空库重复关闭未复现现场停滞；不能把该报告直接归因于通知丢失。源码确认了一个可触发同类现象的路径：排空工作结束后只使用一次 `invoke_from_event_loop`，投递失败被忽略，`closing` 状态没有恢复路径。

后台现在将关闭结果保存在受锁保护的邮箱；UI 仅在关闭期间通过 50ms single-shot timer 接收结果，不依赖跨线程通知。正常关闭仍按 Metadata FIFO、扫描取消、远程缓存排空的顺序完成，不按超时放弃写入。成功后隐藏窗口并退出；失败保留草稿、恢复窗口以便重试。结果消费、shutdown 或窗口销毁后停止轮询，正常空闲没有新增定时工作。关闭阶段日志及五秒仍在排空的警告帮助区分实际等待和界面完成处理。

远程同步原来同样只在 UI 完成回调中解除 busy，通知失败会使关闭永久等待。现在由 worker 的一次性 RAII guard 在同步及离线缓存准备结束后解除 busy，取消 generation 和通知失败均不能阻止释放；迟到回调也不能清除新请求的 UI 进度。Metadata 保存失败时仍排空已取消的远程工作，再恢复管理页指示器，避免旧 generation 留下同步遮罩。

故障回归拒绝所有跨线程 UI 通知，实际启动无效端点同步，检查 busy 释放、草稿持久化、扫描排空、UI 响应及最终隐藏；真实管理锁使第一次保存失败，再验证草稿及同步指示恢复、释放锁后的重复关闭重试。Windows 回归补充真实启动事件循环到主事件循环的空库关闭；`tools/validate-desktop-close.ps1` 使用 owned 临时库验证 WM_CLOSE 和右上角 X 对应的 SC_CLOSE，不操作工作数据库。结果见 [验证报告](Rust_Validation.md)。

worker 排空与 UI/provider 交接现在有不同的完成条件。拒绝新快照后的旧缓存回归等待管理页同步指示及库 gate 都解除，保留原有 fallback 状态、provider 路径、active cache 和快照字节断言，避免在 UI 回调处理前提前读取状态。

## 数据源配置输入与保存（2026-10-09，0.3.6）

Windows 实际窗口复现：服务器名称与地址框可见且启用，点击时短暂获得焦点，随即被拉回“关闭”按钮，键盘输入和粘贴无法进入字段；空地址随后的保存只会返回校验提示。原因是模态焦点定时器默认启动且间隔为 0ms，事件循环反复触发焦点接管。只在同一个回调里连续发送点击和按键的测试会漏掉两次真实输入事件之间发生的焦点抢占。

## 单击播放偏好 CR（2026-10-09）

确认一项 P2：后台保存持有 `config` 锁时，单击播放勾选框的 GUI 回调再次获取该锁，阻塞事件循环。最新选择现通过 `AtomicBool` 提交，由单个后台 worker 合并请求并串行保存；关闭时刷新最新选择并排空保存，保留其他已有偏好。

在合成 500ms 锁竞争的隔离诊断中，同一回调的耗时从修复前 501.0402ms 降至修复后 14.1µs。该结果衡量锁竞争下的回调响应，不代表实盘保存耗时或按钮到音频输出的延迟。

新增回归覆盖正常运行时启用及关闭后自动落盘、锁受阻期间快速切换 5 次，以及立即退出后仍保留最后选择、语言和音量。单独的 GUI 回归覆盖单击、双击、Ctrl/Shift 多选、右键、缺失文件和拖动；后续接入真实 Controller 的刷新回归发现了上述双击状态丢失问题。

## 首次搜索与目录统计后续优化（2026-10-11）

- page/facet 使用两个固定 latest-slot worker，共享 provider、generation、取消标志；facet 先到等待 page，page 失败保留错误，实际目录模型发布后才 Ready。回归覆盖完成顺序、失败、过期回调、模型重建及 Weak provider 身份缓存失效。
- 独占只读连接使用 NO_MUTEX；FTS5 rank 逐请求固定默认 bm25()，自定义库 rank 不改变精确排序。范围筛选的稀疏缺失扣除和 dense fallback 在同一事务内验证；稠密 ID 范围使用最多 1MiB 的临时 bitmap 计算交集，稀疏及极端 i64 范围回退有界 HashSet，保留 SQL 行预算和取消检查。
- 旧 ANALYZE 统计曾使闭包 JOIN 和 SQLite 3.53.2 的 EXISTS flattening 产生平方级工作。rollup 现在固定 descendant 索引方向、物化汇总及 scalar 主键 hydration。256→2048 目录的 VM 步数预算、孤立 ancestor、排序、途中取消/恢复均有确定性回归。
- 缺目录索引时先修复 owned snapshot，同版本迁移实际创建索引；只读原库字节与远程原缓存保留。完整首轮/重复阶段条件和百万实测见 首次搜索性能记录。
